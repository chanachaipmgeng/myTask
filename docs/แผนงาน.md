# แผนงานที่ควรทำต่อ

จัดลำดับจากความคุ้มค่าและความเสี่ยงต่อกติกาคะแนน  
อัปเดตเมื่อจบเฟส — อย่าลบรายการที่ทำแล้ว ให้ย้ายไปหมวด «เสร็จแล้ว» ท้ายไฟล์

---

## เฟสปัจจุบัน (สรุปว่ามีอะไรแล้ว)

- Nest + Postgres + seed + Dev/GitLab login  
- ซิงก์ OpenProject อ่านอย่างเดียว + mapping custom fields  
- คะแนน Implement/R&D + verify  
- แดชบอร์ดทีม · รายชื่อ/โปรไฟล์พนักงาน · ฮับ `/work` · ใบงาน · คิว · ปฏิทิน · mockup  

---

## P0 — ใช้งานจริงกับ myProject

1. **จับคู่ผู้ใช้ OpenProject ครบทีม** แล้ว Sync now บน staging  
2. **สร้าง custom fields ใน myProject ตามตารางในคู่มือ** แล้วใส่ `customFieldN` ใน Integrations  
3. **กฎทีมบันทึกฟิลด์** (estimate, time entry, due ครั้งแรก, Unplanned, Spike) — อบรมสั้น + เช็คลิสต์  
4. **ตรวจ estimate/actual MD** กับชั่วโมงจริง ÷ `hoursPerMd` (ค่าเริ่ม 6)  

## P1 — ปิดช่องว่าง workflow

1. **Writeback assignee** กลับ OpenProject เมื่อ lead อนุมัติ (`OPENPROJECT_WRITEBACK` + สิทธิ์)  
2. **บังคับ MR link ก่อนเข้า Code Review** ให้สอดคล้องกฎ UI/workflow ที่มีอยู่  
3. **นับ reopen จาก activity** ให้เสถียรบนโปรเจกต์จริง (สถานะชื่อไทย/อังกฤษใน statusMap)  
4. **ล็อก firstDueOn** จาก due ครั้งแรกใน OP / CF อย่างชัดเจนใน sync  

## P2 — ข้อมูลย้อนหลังและแจ้งเตือน

1. **KPI snapshot** รายเดือน/ไตรมาส (เก็บผลคะแนนตามช่วง ไม่คำนวณย้อนจากใบปัจจุบันอย่างเดียว)  
2. **ส่ง Teams จริง** จากร่างใน `/teams` (webhook + เลือกประเภท alert)  
3. **ดึง MR จาก GitLab** แทน fixture `/mygit` เมื่อมี OAuth/token  

## P3 — UX / มุมมองงาน

1. **Gantt hierarchy** (Epic→Story) ถ้า myProject มี parent/child  
2. **แก้วันบน Timeline** แบบจำกัด + sync กลับ (ตอนนี้ Gantt อ่านอย่างเดียว)  
3. **รวมนำเข้าไฟล์เข้า `/work` หรือคง `/tickets`** ให้เมนูไม่ซ้ำความเข้าใจ  
4. **สิทธิ์ lead บน Board** แยกจาก member ชัดขึ้น  

## P4 — คุณภาพวิศวกรรม

1. E2E เบาๆ กับ Playwright สำหรับ login → sync mock → `/work/board`  
2. ลดขนาด bundle Gantt (lazy อยู่แล้ว — ดู budget initial)  
3. แยก env ตัวอย่าง staging/production ในคู่มือ
